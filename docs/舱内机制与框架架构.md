# 舱内机制盘点与框架架构

## 盘点范围

在本机 UBOAT 2026.1 Patch 21（Steam build 24913406）批量加载六个玩家艇型。统计舱内场景根对象下的组件，包括未激活、重复和表现用组件。操作入口、交互组件和设备组件各自计数，可能对应同一件设备。实际可用动作还受角色、设备状态和玩法设置影响。

| 艇型 | 舱室 | 操作入口 Activator | 交互组件 Interactable | 设备组件 Equipment |
| --- | ---: | ---: | ---: | ---: |
| VIIB | 8 | 193 | 181 | 295 |
| VIIC | 8 | 198 | 181 | 301 |
| VIIC/41 | 8 | 193 | 181 | 298 |
| IXA | 9 | 196 | 194 | 287 |
| IXC | 9 | 196 | 194 | 287 |
| IXC/40 | 9 | 196 | 194 | 287 |

VIIC 和 IXC 各有一套 TDC，舱内分别有 44 和 45 个相关仪表、旋钮或指示灯组件。IXC 多出独立电机舱，VIIC 有两个电池舱。相同的组件总数仍可能由不同布局和资源构成。

| 功能域 | 游戏中的设备或动作 |
| --- | --- |
| 指挥与航海 | 指挥工位、航海桌、罗经、航向与航线 |
| 操舵与深度控制 | 舵手工位、方向舵、前后深度舵、操舵模式 |
| 压载、配平与压缩空气 | 主压载进水与吹除、纵倾调节、空气压缩机 |
| 推进 | 柴油机、电机、车钟、推进模式、发动机值守和维修 |
| 储能与配电 | 电池充放电、停车充电、舱室配电和设备用电 |
| 观察与探测 | 潜望镜、水听器、舰桥观察。自定义雷达与拖曳声纳在内容包实现 |
| 通信与电子支援 | 电台、测向、天线收放、被动雷达告警 |
| 鱼雷火控 | TDC、潜望镜输入、仪表反馈和管组联动 |
| 鱼雷与发射管管理 | 艇内外库存、搬运、装填、预热维护、各管状态和联锁 |
| 损管与舱内环境 | 渗漏、积水、封堵、排水、通风、空气质量和设备维修 |

| 船员生活与后勤 | 铺位、厨房、厕所、医疗、储物和物资搬运 |

主压载水量、纵倾平衡和舱室积水是不同的游戏状态。原版 `TrimPump` 同时调节纵倾并从所连接的舱柜排水，舱内排水量由实际连接决定。此前将这台泵仅归为纵倾设备的说法需要修正。电池充电已经接入原版 `PlayerShipEngine` 和艇上电力资源，推进和储能适配器可以共享原版状态。未来反应堆内容包可作为游戏内的独立供能模块接入该边界。

来源包括本机游戏程序集 `UBOAT_Data/Managed/com.uboat.game.dll`、上述原版舱内场景，以及[开发者的第一人称与 TDC 更新](https://store.steampowered.com/news/posts/?appids=494840&enddate=1718378968&feed=steam_community_announcements)。

## 架构边界

调用路径为 **内容包 → 公共接口 → 原版适配器 → UBOAT**。注册表保存定义，玩家艇生命周期提供当前运行上下文，两者供公共接口和适配器读取。入口类负责装配原版工位绑定。艇体包提供场景、稳定挂点和工位布局，设备包提供控件资源和设备行为，战役包组合所需内容。

| 层 | 职责 | 当前落点 |
| --- | --- | --- |
| 公共接口 | 稳定 ID、注册与查询、动作请求、状态快照、船只生命周期 | `SubmarineApi`，新增 `StationApi` |
| 舱内注册和绑定 | 将当前艇型、工位 ID、挂点 ID、动作 ID 关联起来，检查重复键和缺失资源 | `Interior/StationRegistry.cs` |
| 原版动作适配 | 查询 `Activator` 上的原版动作和可用性，把请求交给原版船员动作流程，转发设备状态事件 | `Interior/UboatStationAdapter.cs` |
| 原版工位绑定 | 识别原版舵手工位、配平泵及其已有动作 | `Interior/VanillaStations.cs` |
| 内容包 | 模型、动画、第一人称相机和控件、自定义设备行为和战役数据 | 独立发布 |

`SubmarineApi` 保留原有签名和版本。工位接口独立版本化。游戏分别编译源码 Mod，跨包对接继续使用稳定 ID 和可通过委托发现的公共方法。跨包接口可以使用游戏已公开的角色、动作状态类型，具体 Harmony 入口留在适配层。

### 状态与任务的所有权

- 原版工位的角色资格、占位、队列、动画、任务进度及存读档由原版系统持有。工位接口读取状态并提交原版动作请求。
- 第一人称、剖面命令和自动值班在同一个工位复用动作与状态。第一人称使用原版角色视角及设备控件。后续自定义控件通过绑定调用对应能力。
- 工位定义只保存稳定的艇型、挂点、工位和动作 ID。运行时对象只在当前艇有效，换艇、卸载或读档后重新解析，订阅随旧艇释放。
- 新子系统先用具体语义定义边界，例如舵机、推进和电力。设备特例留在对应内容包或适配器里，新增接口前用实际流程验证复用点。

## 实施顺序与验收

1. **工位与原版动作。** 从舵手工位和配平泵接入，验证定位、角色动作查询、向原版动作提交请求及设备状态通知。保留原版玩法设置和人员权限。
2. **第一人称控件和持续任务。** 用一个自制控件验证同一工位的视角绑定、操作反馈和读档恢复。后续用 TDC 和鱼雷装填验证多控件与持续任务。
3. **新设备及子系统。** 用电子支援桅杆验证部署与收回，再扩展到独立探测设备、动力和电力模块。出现第二个具备相同需求的设备时，提炼实际共用的接口。

每个新用例的验收覆盖正常操作、角色或工位不可用、换艇解绑，以及涉及持续状态时的存档读回。已有的 UBOAT 动作通过原版流程验收，开发验证使用独立的临时测试 Mod。

## 0.3.0 验证记录

- 在 IXC 上通过独立测试 Mod 验证了原版工位定位、显式挂点绑定、重复注册拦截和按角色查询动作。
- 舵手值班在测试配置中由原版隐藏。配平泵绑定原版实际配置的 `SwitchPowerAction`。一次完整的船员动作改变了泵的开关状态，订阅方收到了状态通知。
- IXC 换到 VIIC 后，两个工位重新解析，旧艇订阅释放了工位和设备引用。
- 批处理测试中，关泵请求进入原版动作流程，测试窗口内仍未确认完成。重复测试也出现过一次启动动作未在窗口内完成。完整开关往返、第一人称手动操作和读档恢复待正常游戏会话验收。

## 0.4.0 接入边界

[机制接口接入说明](机制接口接入说明.md)已补齐 12 类机制的入口。工位适配通过原版动作执行，模型控件和自定义子系统使用独立的当前艇注册表，换艇时解绑。原版 TDC、鱼雷管和制导弹药分别归属火控接入、原版设备接入和独立内容包。新艇采用数字火控时可注册自己的提供方。

本轮先完成公共接口与构建验证，游戏内功能验收合并到下一次统一测试。
