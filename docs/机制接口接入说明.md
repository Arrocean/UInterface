# 机制接口接入说明

## 选择接入方式

- 复用原版设备时，先通过 `ComponentApi.GetShipComponents(componentType, includeInactive)` 枚举当前艇的设备，或通过 `TryGetMountedComponent(mountId, componentType, out component)` 精确定位挂点上的组件。获得组件后使用它的原版公共方法。挂点定义由艇体内容包提供。
- 舱内需要船员执行的操作走 `StationApi`。它查询角色及工位的原版条件，然后提交原版动作。设备包可复用这条路径处理维护、装填、搬运、阀门和开关。
- 设备包提供新的数字控制台、动力设备或其他行为时，可在当前艇注册自己的子系统和控制件。内容包拥有模拟、输入界面、动画、状态与存档规则，通过稳定的 ID 让其他模块发现能力。

接口方法可通过游戏已加载的 `UInterface` 公共类型绑定为委托，参见 [README 的 C# 接口说明](../README.md#c-接口)。API 在游戏主线程使用。船只、设备和动作对象属于当前游戏场景，每次换艇或读档后应重新获取。

## 工位与原版动作

`GetStations(stationId)` 枚举匹配的舱内工位。同一类可以有多个实例。稳定工位 ID 与挂点一一绑定时，可以使用 `TryGetStation` 精确取单项。

`QueryNativeActions(station, actor)` 返回该工位对指定角色可见的原版动作及其可用状态。`RequestNativeAction(station, template, actor)` 使用查询返回的动作模板提交请求，提交前重新检查工位归属和原版可用状态。请求成功表示动作进入原版流程，完成状态取决于船员和设备。已有的命名动作注册、查询和请求接口继续可用。

原版艇提供以下工位 ID，由 `VanillaStations.cs` 映射到已查到的原版标签。新艇可在 `UInterfaceStations` 中将相应 ID 指向自己的挂点。

| 功能域 | 接入入口 |
| --- | --- |
| 指挥与航海 | `uinterface.command`、`uinterface.navigation`，或用 `NavigationApi` 取得航海桌 |
| 操舵与深度 | `uinterface.helm`、`uinterface.dive-planes`，以及 `NavigationApi` 的舵组件、原版航向预设、深度与目标深度 |
| 压载、配平与压缩空气 | `uinterface.ballast-valves`、`uinterface.trim-pump`、`uinterface.compressors`，以及 `EngineeringApi` 的压载舱、进水设定和配平泵 |
| 推进 | `uinterface.diesel-engine`、`uinterface.electric-engine`、`uinterface.snorkel`，以及 `EngineeringApi.TryGetPropulsion` |
| 储能与配电 | `EngineeringApi.TryGetResources`、`TryRequestStationaryCharging`，以及通过 `ComponentApi` 定位配电板并调用原版操作 |
| 观察与探测 | 攻击与观察潜望镜、听音室工位，`SensorsApi` 提供原版探测器与观测结果 |
| 通信与电子支援 | `uinterface.radio`、`SensorsApi.TryGetRadio`。自定义桅杆可用 `DeploymentApi` 接入 |
| 火控 | `uinterface.tdc`、`uinterface.fire-control-boxes` 和可选的 `VanillaFireControlApi` |
| 鱼雷管与储位 | `uinterface.torpedo-tubes`、`uinterface.torpedo-breeches`、`uinterface.torpedo-stores`，以及独立的 `TorpedoTubeApi` |
| 损管与舱内环境 | `uinterface.workshop`、`uinterface.ventilation`，以及 `EngineeringApi.GetCompartments` 和设备上的原版维修动作 |
| 舱室通行 | `uinterface.hatches`、`uinterface.ladders` 和原版组件状态 |
| 船员生活与后勤 | `uinterface.galley`、`uinterface.main-storage`、`uinterface.officer-beds`，以及 `CrewServicesApi` 的船员名单和物资储存 |

## 自定义控件、桅杆与子系统

以下注册返回 `IDisposable`。释放可撤销本次注册。换艇后框架会释放旧艇的绑定，内容包为新艇重新注册。重复 ID 或资源尚不可用时返回 `null`。

- `ControlApi.RegisterButton(controlId, mountId, press)` 配对物理按钮与逻辑请求，`TryPress` 调用设备包提供的回调。
- `ControlApi.RegisterAxis(controlId, mountId, read, set)` 配对连续控件与设备状态，提供 `TryReadAxis`、`TrySetAxis` 和 `TryGetControlMount`。模型包的第一人称输入或数字界面调用这些方法，设备包负责其规则和反馈。
- `DeploymentApi.RegisterDeployable(equipmentId, request, readState)` 绑定设备已有的收放请求与状态。其他模块通过 `RequestDeployment` 和 `TryGetEquipmentState` 调用，实际动画、联锁与状态由设备包控制。
- `SubsystemApi.RegisterProvider(subsystemId, provider)` 注册艇内可选的子系统。`TryGetProvider(subsystemId, contract, out provider)` 用双方约定的类型查询。消费方和内容包决定契约，例如数字火控或供能系统。

## 火控与弹药的职责

`VanillaFireControlApi.TryGetTdc` 和 `TryGetFireControlBoxes` 获取艇上可选的原版组件。艇型选择复用原版 TDC 或提供自己的数字火控子系统。火控演算、鱼雷参数、制导行为和弹药定义由对应内容包拥有。

`TorpedoTubeApi.GetTorpedoTubes` 单独提供原版管组的组件引用。维护、搬运和装填沿用管组及储位已有的船员动作，弹药内容包可据此接入自身的数据和行为。

## 验收范围

0.4.0 实现上述接入接口并进行构建及包结构检查。统一游戏内验收覆盖艇型差异、多工位定位、动作权限与任务完成、控件反馈、收放状态、换艇与读档，以及没有原版 TDC 的内容艇。
